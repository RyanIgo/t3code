# Fleet board fork

A UI-only fork of [pingdotgg/t3code](https://github.com/pingdotgg/t3code) that adds a
**Board** page: every thread from every paired machine, one row per project, columns
**Needs me / Running / Queued · idle / Done · unreviewed**.

Only the web client changes. The `t3` server, its database, and the other machines
stay stock. The board reads the threads the client already holds for each paired
environment, and sorts them with the sidebar's own status rules
(`resolveSidebarThreadStatus`, `hasUnseenCompletion`), so the board and the sidebar
always agree.

## Set up a machine

Needs T3 Code installed (stable channel) and this repo cloned. `feat/fleet-board` is the fork's
default branch, so a plain clone is enough:

```sh
gh repo clone RyanIgo/t3code && cd t3code   # or: git clone https://github.com/RyanIgo/t3code.git
```

`main` stays a mirror of upstream; the board lives on `feat/fleet-board`.

```sh
fleet/setup.sh
```

That installs [vp](https://viteplus.dev) if missing (it provides the pinned Node 26 and pnpm, and is
added to `~/.zshrc`/`~/.bashrc`), runs `vp i` and the board tests, builds the client, moves t3 to the
version the fork is based on (`git describe --tags`) if needed, backs up the upstream client to
`client.upstream`, swaps this one in, and restarts the service. Then reload T3 and click **Board** at the top of
the sidebar (or ⌘K → Open board).

Run from a T3 chat, the update and restart step continues in a separate systemd job (the restart
would otherwise kill the chat), so the chat drops for a moment; the output is in `fleet/install.log`.

Later, after pulling changes or a `t3 update` (which puts the upstream client back):

```sh
fleet/install-client.sh            # rebuild and reinstall
fleet/install-client.sh --update   # same, moving t3 to the fork's version first
fleet/install-client.sh --restore  # undo: put the upstream client back
```

`--update` never downgrades t3. If this machine runs a newer t3 than the fork, rebase the fork
(below) instead.

## See other machines on the board

Projects and threads live in each machine's own `~/.t3/userdata`, not in this repo. To see another
machine's work, pair it into the one you look at: on the other machine run
`t3 serve --tailscale-serve`, then on this one go to Settings → Connections → Add environment.

## Pull in upstream

```sh
git fetch upstream --tags
git rebase v<new-version>        # stable tags only; nightlies move several times a day
vp i && vp test run apps/web/src/components/board
```

If a rebase conflicts, it will be in the upstream files above. Each change is small and marked;
re-apply it by hand.

## Dev loop

Never point a dev server at `~/.t3/userdata`. Seed an isolated copy and run against it:

```sh
node apps/server/scripts/migrate-dev-db.ts --base-dir "$PWD/.t3"
node scripts/dev-runner.ts dev --home-dir "$PWD/.t3" --no-browser   # open the printed pairingUrl, then /board
```
