# Fleet board fork

A UI-only fork of [pingdotgg/t3code](https://github.com/pingdotgg/t3code) that adds a
**Board** page: every thread from every paired machine, one row per project, columns
**Needs me / Running / Queued · idle / Done · unreviewed**.

Only the web client changes. The `t3` server, its database, and the other machines
stay stock. The board reads the threads the client already holds for each paired
environment, and sorts them with the sidebar's own status rules
(`resolveSidebarThreadStatus`, `hasUnseenCompletion`), so the board and the sidebar
always agree.

## Test on a machine

1. Pair the other machines into the one you'll look at: on each one run
   `t3 serve --tailscale-serve`, then on the viewer go to Settings → Connections →
   Add environment.
2. The viewer must run the same t3 version the fork is based on (`git describe --tags`):
   `t3 update 0.1.5 -y`.
3. In this repo (Node 26 via `.nvmrc`, `vp i` once): `fleet/install-client.sh`.
   It builds the client, backs up the upstream client to `client.upstream`, swaps it in,
   and restarts the service.
4. Open T3 → **Board** in the sidebar footer.
5. Undo any time: `fleet/install-client.sh --restore`.

A `t3 update` installs a fresh upstream client, so re-run the installer afterwards.

## Pull in upstream

```sh
git fetch upstream --tags
git rebase v<new-version>        # stable tags only; nightlies move several times a day
vp i && vp test run apps/web/src/components/board
```

If a rebase conflicts, it will be in the two sidebar files above. Re-apply the one-line
change in each.

## Dev loop

Never point a dev server at `~/.t3/userdata`. Seed an isolated copy and run against it:

```sh
node apps/server/scripts/migrate-dev-db.ts --base-dir "$PWD/.t3"
node scripts/dev-runner.ts dev --home-dir "$PWD/.t3" --no-browser   # open the printed pairingUrl, then /board
```
